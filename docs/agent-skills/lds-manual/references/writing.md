# 매뉴얼 라이팅

상위 기준은 설치된 LDS Core의 `docs/foundations/writing.md`, `voice-and-tone.md`,
`docs/policies/COPY_REVIEW_CONTRACT.md`다. 제품 실제 동작·정식 용어가 스타일 제안보다 우선한다.

- 단계 제목은 짧은 행동형: 「로그인」 선택, 설치 결과 확인.
- 본문은 차분한 설명체: 누릅니다·선택합니다·확인합니다. 제품의 승인된 경고 문구는 유지한다.
- 한 문장에 한 목적. 추상적인 처리·갱신·대조를 남발하지 말고 사용자가 관찰하거나 할 일을 쓴다.
- 실제 버튼명을 「 」로 표시한다. 실제 「확인」 버튼을 스타일 규칙 때문에 다른 이름으로 바꾸지 않는다.
- 파일명·주소·고유명사·버전·수치를 보존한다. 원문 오류가 의심되면 제품 자료로 확인한다.
- 문서 메타는 실제 문서 버전을 적는다. 근거 버전은 별도 provenance로 관리하며 임의로 '기반'을 붙이지 않는다.
- 일반 문장의 말줄임은 …, 날짜는 ISO를 기본으로 한다. 실제 화면의 인용 문자열은 원문을 우선한다.
- 요청 전송·확인 표시·현장 조치 완료를 구분한다. 시스템이 확인하지 않은 결과를 완료로 쓰지 않는다.
- 보안 설정은 무엇을, 언제 변경하고 복구하는지 구체적으로 쓴다. 안전·권한 영향을 추측하거나 약화하지 않는다.
- '이 매뉴얼은…' 같은 문서 소개를 행동 전 확인사항 Callout에 섞지 않는다.
- 제목·본문·그림·캡션을 한 과업 세트로 읽는다. 내용이 이미 자연스러우면 그대로 둔다.

예: '영상의 갱신 확인' → '영상이 계속 바뀌는지 확인'.
'확인 처리됨'을 '문제 해결 완료'로 바꾸는 것은 윤문이 아니라 제품 의미 변경이므로 금지한다.
