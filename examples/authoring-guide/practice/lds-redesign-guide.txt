# 기존 매뉴얼의 LDS 재디자인 기준
원본 PDF/PPTX의 각 쪽에서 제목·절차·설명·주의사항·표·화면을 확인한다. 판독되지 않은 내용은 추측하지 않고 쪽 번호와 누락 항목을 알린다.
내용·절차 순서·버튼 이름·수치·주의사항을 보존한다. 원본 화면을 재사용하고 없는 기능이나 화면을 생성하지 않는다. 설명을 줄여 중요한 조건을 생략하지 않는다.
먼저 대표 1~2쪽의 시안을 보여 주고 피드백을 반영한 뒤 전체 문서에 적용한다. 원본은 덮어쓰지 않는다.
LDS Core/Theme의 색·폰트·타입·간격·곡률과 실제 컴포넌트를 사용한다. 첨부한 적용 예시 PDF를 레이아웃 참고로 삼는다. 패키지를 실행하지 못한 경우 LDS 실행을 검증했다고 주장하지 않는다.
원본→결과 쪽의 대응, 설명·이미지 누락, 숫자·고유명사 변경을 확인한다. 모든 출력 쪽을 렌더링해 잘림·겹침·가독성을 확인한다.
문구는 사용자 과업별로 함께 읽는다. 대상·행동·확인할 결과를 구체적으로 쓴다. 문구와 화면의 버튼명을 일치시킨다. 기계적 금칙어 검색을 자연스러움 검토로 대신하지 않는다.
PDF를 실제 생성해 첨부한다. PPTX를 요청받았다면 텍스트와 이미지의 편집 가능 여부도 확인한다. 만들지 못한 파일을 완성했다고 보고하지 않는다.

# Compact A4 구성

## LDS 공식 토큰과 매뉴얼 선택의 구분

Core/Theme가 색·폰트·타입·간격·곡률 값을 소유한다. 다음 표의 역할 배정과 A4 지오메트리는
**Manual compact 프리셋**의 선택이다. Core의 값을 바꾸거나 다른 제품에 강제하지 않는다.

| 역할 | 매핑 |
|---|---|
| 표지 제목 | title2, ExtraBold |
| 섹션 제목 바 | headline1, Bold, radius-8 |
| 단계 제목·번호 | headline2, 17px / 24px / 600 |
| 보조 제목 | body1, 16px / 24px / 600 |
| 본문·표·요청문 | label1 reading, 14px / 22px / 400 |
| 메타·문서 프레임 자료 이름 | label2 reading, 13px / 20px |
| 캡션·페이지 번호 | caption1, 12px / 16px |
| 콜아웃 | 실제 Core Callout compact: 제목 16px / 24px / 700, 본문 14px / 20px; 내부 스타일 변경 금지 |
| 문서 표 외곽 / 화면 모서리 | radius-8 / radius-xs |

요청문은 Core Blockquote에 전달하는 Manual 소유 문단에 본문 타입을 적용한다. Core 내부 선택자나 토큰을 재정의하지 않는다. 단계 설명 스타일은 단계 제목 아래의 설명에만 적용하여 요청문·캡션·프레임 제목으로 새지 않게 한다.

페이지는 A4 210×297mm, 좌우·위 여백 13mm, 하단 콘텐츠 예약 20mm다.
페이지 번호는 아래 9mm에 위치하며 콘텐츠와 겹치지 않는다.

## 간격은 관계로 결정

| 관계 | LDS 토큰 |
|---|---|
| 제목 바 → 도입 문장 | space-4 (16px) |
| 단계 제목 → 설명 | space-1 (4px) |
| 설명 → 해당 화면 | space-3 (12px) |
| 화면 → 캡션 | space-2 (8px) |
| 한 단계 끝 → 다음 단계 | space-6 (24px) |
| 본문 → 콜아웃 | space-4 (16px) |

steps는 순서 목록으로 구성하며 번호와 제목은 같은 타입 역할을 쓴다.

## 단계·보조 안내·콜아웃의 선택

다음은 Core 컴포넌트를 매뉴얼에 배정하는 **LDS Manual 작성 기준**이다. LDS Core 전체의 사용 규정으로 확대하지 않는다.
문장 길이나 상시 노출 여부가 아니라, 사용자 과업에서의 역할로 선택한다.

| 역할 | 구성 | 예시 |
|---|---|---|
| 사용자가 수행할 행동·결과 확인 | 번호형 steps | 수정 요청 보내기 → 수정 결과 확인하기 |
| 별도 제목이 있는 보충·선택·예외 안내 | 제목이 있는 실제 Core Callout | 편집용 PPTX도 필요한 경우, 설명만 받고 파일이 없을 때 |
| 이미지 설명 | figure의 캡션 | 원본 PDF 첫 쪽, 확대 영역 설명 |

별도의 help 표현은 사용하지 않는다. 본문에 자연스럽게 이어지는 짧은 설명은 일반 문단으로 둔다.
일반적인 보충·선택·예외 안내에는 `signal`을 사용한다. 실제 위험이 없는 안내를 경고색으로 강조하지 않는다.
같은 역할의 안내는 문서 전체에서 같은 구성으로 표현한다.
제목 없는 긴 Callout, 고립된 보조 제목, 페이지마다 다른 캡션 크기를 만들지 않는다.

## 콜아웃 위치 판단

짧은 단일 과업 페이지에서는 보충 콜아웃을 상단 또는 하단 **한곳에 모두 모은다**.
상단과 하단으로 나누어 배치하지 않는다. 기본 절차를 먼저 읽는 페이지는 하단을 기본으로 하며,
시작 전에 함께 확인해야 하는 안내라면 상단에 묶는다. 이는 LDS Manual의 배치 기준이다.

| 역할 | 위치 |
|---|---|
| 일반적인 선택·보충·예외·참고 | 페이지별로 한곳에 묶음. 기본 절차 → 하단 보충 안내를 우선 |
| 시작 전에 함께 확인해야 하는 안내 | 상단 한곳에 묶음 |
| 행동 전에 반드시 알아야 하는 주의·조건 | 예외적으로 해당 단계 바로 앞 |
| 결과 확인 | 해당 행동 뒤의 번호형 단계 |

긴 페이지나 여러 과업이 섞인 페이지는 과업 단위로 나누어 관련성을 유지한다.
실행 후 확인이 콜아웃에 섞이면 해당 확인 단계로 분리한다.
검토할 때는 보충 안내가 한곳에 모였는지, 기본 절차가 끊기지 않는지,
필수 주의사항을 읽기 전에 행동할 위험이 있는지 확인한다.
빈 공간이나 넘침 회피만을 이동 근거로 삼지 않는다.

## 화면과 분량

로고는 공식 LDS Theme 자산을 원래 비율·35mm 폭으로 표지 제목 위에 둔다. 문서 정보는 한 줄에 두 항목을 배치하고, 주소 등 주요 값은 labeled list의 emphasis로 강조한다.

한 장의 화면은 본문 폭 또는 reading(170mm), 두 장은 compact(151mm) 폭을 기본으로 한다. 세로 화면은 columns를
사용할 수 있다. 레이아웃은 내용에 맞춰 선택하며 모든 페이지를 같은 도식으로 채우지 않는다.
스크린샷 자체의 버튼 글자가 읽히지 않으면 확대 상세를 추가하거나 페이지를 나눈다.
본문 font-size를 낮추거나 변형 scale로 전체 페이지를 몰래 축소하지 않는다.
A4 미리보기의 가로 스크롤은 의도된 매체 동작이며 반응형 앱이라고 설명하지 않는다.

# 매뉴얼 라이팅

상위 기준은 설치된 LDS Core의 `docs/foundations/writing.md`, `voice-and-tone.md`,
`docs/policies/COPY_REVIEW_CONTRACT.md`다. 제품 실제 동작·정식 용어가 스타일 제안보다 우선한다.

- 단계 제목은 짧은 행동형: 「로그인」 선택, 설치 결과 확인.
- 본문은 차분한 설명체: 누릅니다·선택합니다·확인합니다. 제품의 승인된 경고 문구는 유지한다.
- 한 문장에 한 목적. 추상적인 처리·갱신·대조를 남발하지 말고 사용자가 관찰하거나 할 일을 쓴다.
- 실제 버튼명을 「 」로 표시한다. 실제 「확인」 버튼을 스타일 규칙 때문에 다른 이름으로 바꾸지 않는다.
- 파일명·주소·고유명사·버전·수치를 보존한다. 원문 오류가 의심되면 제품 자료로 확인한다.
- 문서 메타는 실제 문서 버전을 적는다. 근거 버전은 별도 provenance로 관리하며 임의로 '기반'을 붙이지 않는다.
- 일반 문장의 말줄임은 …, 날짜는 ISO를 기본으로 한다. 실제 화면의 인용 문자열은 원문을 우선한다.
- 요청 전송·확인 표시·현장 조치 완료를 구분한다. 시스템이 확인하지 않은 결과를 완료로 쓰지 않는다.
- 보안 설정은 무엇을, 언제 변경하고 복구하는지 구체적으로 쓴다. 안전·권한 영향을 추측하거나 약화하지 않는다.
- '이 매뉴얼은…' 같은 문서 소개를 행동 전 확인사항 Callout에 섞지 않는다.
- 제목·본문·그림·캡션을 한 과업 세트로 읽는다. 내용이 이미 자연스러우면 그대로 둔다.

예: '영상의 갱신 확인' → '영상이 계속 바뀌는지 확인'.
'확인 처리됨'을 '문제 해결 완료'로 바꾸는 것은 윤문이 아니라 제품 의미 변경이므로 금지한다.
